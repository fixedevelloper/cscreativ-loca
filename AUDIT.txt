2. FAILLES DE SECURITE CRITIQUES (NOUVELLES)
--------------------------------------------------------------------------------
S1  DocumentController::download
    Pour un locataire, "$document->is_shared" suffit a autoriser, sans
    verifier le contrat. Toutes les quittances sont creees is_shared=true.
    -> N'importe quel locataire telecharge les quittances/documents
       partages de TOUS les locataires de la plateforme (enumeration d'id).

S2  DocumentController::store + Jobs/GenerateContractPdf
    contract_id valide par "exists" seulement. Avec type=contract, le job
    genere le PDF du contrat d'un AUTRE client et l'attache au document
    de l'attaquant.
    -> Exfiltration du bail de n'importe quel client + injection de
       documents dans l'espace de la victime.

S3  DocumentController::index / download
    Un agent voit et telecharge TOUS les documents, pas seulement ceux des
    bailleurs qui lui sont rattaches.

S4  Service/MomoService.php
    logger($token) et log du body complet : token d'acces MoMo en clair
    dans les logs.

S5  Frontend options.ts + axiosServices.ts
    NextAuth logue result.data (contient le token API) ; l'intercepteur
    Axios logue le corps de chaque requete (mots de passe) dans la
    console du navigateur.

S6  config/sanctum.php (expiration => null) + frontend
    Tokens Sanctum sans expiration ; signOut() n'appelle pas /api/logout ;
    token toujours expose cote client (session.token + fallback
    localStorage).

  chaque requete API ; intercepteurs enregistres plusieurs fois

A. SECURITE FRONTEND - confirmations et nouveaux constats

F1  Fichier : (absence de middleware.ts)
    Constat : Aucun middleware.ts a la racine. La seule protection des
